# 共享包规则

本文件适用于 `packages/`，只能补充根目录规则，不能放宽它。

## 边界

- 共享包不得依赖 `apps/`、React、Express、Mongoose 或浏览器运行时。
- 优先提供纯函数、类型和运行时 schema；同一输入必须产生确定结果。
- `shared` 维护跨端基础契约和 Blockly 命令中间表示。
- `parts-schema` 维护零件注册表、版本和合法结构。
- `geometry` 维护可解释的几何计算，不声明制造可行性。
- `flight-check` 维护规则检查与警告，不声明真实适航或飞行安全。
- 任何飞行证据包必须来自负责人批准、版本化且由服务端控制的注册表；客户端提交的 evidence、`verified` 状态或规则结果均不可信。
- 发布、徽章或评分依赖飞行检查时，服务端必须按同一规则版本和证据版本重新计算。

## 改动要求

- 先写失败测试，再改变共享行为。
- 新增跨端字段时同时定义版本、兼容策略、运行时校验、迁移影响和所有调用方。
- 跨包产品常量只能有一个来源，并由同一组 fixture 验证所有消费者；发现现有冲突时先登记并冻结规则，不能任选一份复制。
- 不把应用页面、HTTP 处理、数据库模型或环境相关逻辑下沉到共享包。
- 先运行目标包测试和类型检查，再运行根目录 `pnpm run harness` 与 `pnpm run ci`。
