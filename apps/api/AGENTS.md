# API 模块规则

本文件适用于 `apps/api/`，只能补充根目录规则，不能放宽它。

## 结构

- `src/` 保持 CommonJS JavaScript，不引入 TypeScript。
- `app.js` 负责可测试的应用装配，`server.js` 只负责启动；模块导入不得产生监听端口等副作用。
- 新增或修改的路由只保留 HTTP 转换，并把可复用业务规则逐步下沉到可独立测试的领域模块；不得继续扩张现有路由中的内嵌业务和数据访问。数据库与对象存储通过适配器接入。
- 跨端输入输出使用共享运行时契约，不手写第二份格式。

## 数据与权限

- 实现前明确请求、响应、权限、错误和幂等行为。
- 每个受保护操作验证身份、角色、资源存在性、所有权和当前状态。
- 忽略客户端提交的 owner、role、public、audit、score、fork、manufacturing 和 flight 等权威性声明。
- 可重试写操作使用唯一约束或幂等键；列表响应保持稳定分页结构。
- 限制上传类型与大小，阻止路径穿越，并向客户端返回安全错误。
- 破坏性维护脚本必须有显式保护、范围预览、备份和回滚说明。

## 测试与验证

- 使用 `node:test` 先写失败测试。
- 至少覆盖未登录、越权、非法输入、正常路径、重试、所有权和依赖失败。
- MongoDB 索引、事务、对象存储等依赖真实语义的行为使用集成测试验证，不能只由内存 mock 证明。
- 先运行 API 目标测试和 `pnpm check:api`，再运行根目录 `pnpm run harness` 与 `pnpm run ci`。
