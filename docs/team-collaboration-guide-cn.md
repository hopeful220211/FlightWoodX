# 全队协作操作手册(大白话版)

> 给非技术负责人监督用,也给每个工程师/AI 干活用。
> 配套技术版见同目录 `parallel-agents-worktree-sop.md`。
> 立于 2026-06-16「三个人挤一个文件夹差点丢活」之后。

---

## 一、今后每人在哪个文件夹干活

电脑 `Projects` 文件夹下,现在有 4 个并排的文件夹:

| 文件夹 | 谁用 | 说明 |
|---|---|---|
| `flightwoodx`(主) | **谁都不在里面直接改东西** | 大家的"干净底本",只看不动 |
| `fwx-projecthub` | 做"项目主页"的工程师 | 他的专属工作区 |
| `fwx-share` | 做"作品分享"的工程师 | 他的专属工作区 |
| `fwx-growth` | 做"成长体系"的工程师 | 他的专属工作区 |

**铁律一:每人只在自己的文件夹里干活。不进别人的,也不在主文件夹里改。** 这样永远不会再互相覆盖。

---

## 二、每天怎么开工

1. 打开**自己的**那个文件夹(例:做项目主页的,就进 `fwx-projecthub`)。
2. 在里面正常干活:改代码、做功能、开预览。
3. 全程不用管别人——你这个文件夹和别人的完全隔开。

**派 AI 干活时,开头先说这句**(负责人可直接复制):
> 你的工作文件夹是 `/Users/nesty/Projects/fwx-XXX`,所有事情都在这里面做,**不要去别的文件夹、也不要去主文件夹**。

---

## 三、干完一段怎么"存档"(存好、不丢)

在自己的文件夹里,三个动作:
1. **打包**改动
2. **存档**(写一句话说明这次做了啥)
3. **上传云端**

> 负责人怎么监督:让工程师存完后,**给你一个 GitHub 链接**,你点进去能看到"这次存了哪些东西、改了什么"。看不到链接 = 没存好。

---

## 四、怎么验收(负责人的唯一标准)

**唯一标准:你能照着工程师给的"点击路径",自己亲眼在网站上看到功能正常。**
工程师跑的测试、绿色的勾,是他自己的事,不算给你的证据。

每次让工程师按这四条给你汇报:
1. **做完了啥**(一句话,用户角度:"孩子打开 X,能看到/能做 Y")
2. **怎么自己验**(打开网站 → 点哪 → 应该看到啥)
3. **对应 RFC-011 哪部分**(写章节,确认没跑偏)
4. **有没有动公共文件**(老实说:"只动自己新文件",或"改了 X,可能和别人撞,需协调")

---

## 五、另外两位:怎么把自己的活从"总备份"搬回自己文件夹

他们之前的活,现在安全躺在云端的**总备份** `snapshot/wip-all-2026-06-16` 里(一点没丢)。各自搬回步骤:

1. 进自己的文件夹(`fwx-projecthub` 或 `fwx-share`)。
2. 从总备份里,**把属于自己的文件复制取出来**到当前文件夹。
   - 给工程师的技术做法:`git checkout snapshot/wip-all-2026-06-16 -- <自己的文件或文件夹路径>`(这是"复制取出",不会动到备份本身)。
3. 自己核对:取出来的确实是自己的活、没拿错。
4. 存档 + 上传(见第三节)。

⚠️ **关键**:之前三个人的活是混在一起的,**取的时候各自认领自己的部分**——谁做的功能,谁最清楚自己改了哪些文件。
✅ **不怕取错**:总备份原样一直在,丢不了,取错了重来一次就行。

**铁律二:要改这些公共文件,先在群里说一声、约好谁改、什么时候改,绝不两个人同时改。** 改完单独告诉负责人。

---

## 七、贴墙上的四条铁律

1. **只在自己的文件夹干活**,不碰别人的、不碰主文件夹。
2. **公共文件要改,先打招呼**,别同时动。
3. **干完就存档上传**(打包 → 存档 → 上传),别攒着。
4. **给负责人验收**:一句话 + 一条点击路径,让他亲眼看到功能正常。
