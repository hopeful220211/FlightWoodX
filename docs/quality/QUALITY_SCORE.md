## 评分方法

每个维度按 0–4 分评定；缺少适用 commit 或证据时记“待验证”，不以推测补分。

| 分数 | 含义 |
|---:|---|
| 0 | 要求缺失、已知不满足或存在阻断性缺陷 |
| 1 | 要求已写明，尚无足够实现证据 |
| 2 | 有实现和局部测试，关键失败路径或环境未验证 |
| 3 | 相关自动化与规定人工路径在指定 commit 通过 |
| 4 | 第 3 级持续通过，并有目标环境、运行观测和恢复证据 |

评估八个等权维度，总分为 `已评维度得分之和 / 已评维度满分`。不得把“待验证”按 0 分混入，也不得用平均分掩盖发布阻塞。

| 维度 | 主要检查 | 当前分数 |
|---|---|---|
| 产品真值与证据边界 | 文案、规则检查、视觉仿真、制造和实飞声明一致 | 待验证 |
| 核心流程 | 六段主线及正常、失败、刷新和恢复路径 | 待验证 |
| 数据与契约 | 单一来源、运行时校验、身份映射、幂等和迁移 | 待验证 |
| 安全与隐私 | 鉴权、归属、输入、密钥、滥用防护和未成年人保护 | 待验证 |
| 可靠性与恢复 | 冲突、重试、外部服务失败、观测、备份和恢复 | 待验证 |
| 测试与持续集成 | 相关测试、根命令、远端门禁和失败不放行 | 待验证 |
| 用户体验与性能 | 目标视口、无障碍、错误反馈、资源和交互性能 | 待验证 |
| 部署与运行 | 目标环境回读、监控、告警、容量和回滚 | 待验证 |

## 发布门槛

- 总分只用于比较版本，不能覆盖 [`CURRENT_STATUS.md`](../../CURRENT_STATUS.md) 中的 P0 阻塞。
- 任一安全、数据丢失、权限、未成年人保护、硬件/制造/实飞证据阻塞存在时，发布结论仍为未通过。
- 只有 `AGENTS.md` 完成定义全部满足，且负责人批准合并、部署和工程承诺时，才能称为发布完成。

## 更新记录格式

每次评分写明：评估日期、commit、环境、各维度分数、证据链接、未通过项、发布门槛结果和复评条件。分数变化必须由新证据支持；不能因文档新增、计划关闭或 RFC 获批自动加分。
