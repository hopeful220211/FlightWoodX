# 可靠性要求

> 状态：可靠性要求生效；当前基线以 `CURRENT_STATUS.md` 为准
>
> 更新时间：2026-08-15
>
> 适用范围：核心流程、API、正式数据、外部存储、部署和恢复
>
> 替代关系：新增可靠性验收框架，不替代 `AGENTS.md` 的完成定义、`ARCHITECTURE.md` 的数据边界或 `CURRENT_STATUS.md` 的验证事实

可靠性的最低含义是：用户不会因失败得到虚假成功、静默丢失作品或运行错误数据；相同输入和重试有可解释结果；故障可以发现、停止并恢复。

## 不变量

1. 登录用户作品以服务端 `DroneDesign` 为正式来源；程序明确绑定作品；不得增加第三套隐式同步来源。
2. 创建、同步、发布、提交和 fork 可安全重试。重复请求不产生重复正式记录，同键不同载荷返回确定冲突。
3. 坏快照、坏 XML、坏几何和不合法状态在边界被拒绝，原有有效数据保持不变。
4. 网络、数据库或对象存储失败时保留可恢复数据，界面明确失败，不回退到 DEMO、mock 或旧缓存并显示成功。
5. 多端同时修改进入显式冲突；冲突协议获批前，不按客户端时间自动覆盖或合并结构数据。
6. 视觉仿真的开始、停止、失败和竞态有确定结果；运行的是当前作品绑定的当前程序。
7. 相同合法输入产生确定的几何与导出内容；缺失二维源进入清单，不生成伪造轮廓。
8. 数据迁移可重跑、可对账、可回滚；发现重复映射或引用缺失时停止并人工处理。

## 核心路径失败行为

| 环节 | 失败时必须发生 |
|---|---|
| 零件创建或选择 | 拒绝坏来源或坏契约，保留原作品并说明原因 |
| 拼装 | 非法连接不落入正式快照；操作失败不伪装成已添加 |
| Blockly | 损坏 XML 不覆盖草稿；编译错误定位到当前作品和程序 |
| 视觉仿真 | 可停止；错误不残留为成功结果；重复启动和切换作品有确定行为 |
| 保存 | 本地内容保留；失败可见；重试幂等；刷新后状态可解释 |
| 部分导出 | 缺失项明确列出；写文件失败不报告完整导出；再次导出内容可对比 |

## 服务与运行验证

- 使用隔离账号和对象验证真实 MongoDB、唯一索引或事务并发、OSS/S3 上传、替换、删除、STS 边界和失败恢复。
- 健康检查必须反映关键依赖，不把进程存活等同于服务可用。
- 结构化日志、错误聚合、指标和告警能定位失败路径，同时遵守隐私与密钥规则。
- 备份必须通过恢复演练证明可用；部署和迁移记录回滚条件与实际回读。
- 可用性、延迟、错误预算、恢复时间和数据恢复点目前没有获批数值；在有生产环境、责任人和测量方式前不得自行填写。

## 证据要求

自动化需要覆盖正常、非法、重复、并发和恢复路径；人工证据记录页面、操作、视口、浏览器、网络或依赖故障注入方式与结果。当前已知缺口从 [`CURRENT_STATUS.md`](../../CURRENT_STATUS.md) 和 [`TECH_DEBT.md`](./TECH_DEBT.md) 读取。
