## 目标与边界

目标是把 Harness Engineering 变成仓库可读取、可执行和可持续维护的基础，而不是新增一段提示词。

本轮没有修改界面文字。应用侧只收紧服务端备用 CAD 导出的目录、输入和授权边界，并修复一个只在原开发机可运行的检查脚本；没有把浏览器、真实外部服务、硬件、制造、实飞或目标环境标为已验证。

## 结果

1. 根 `AGENTS.md` 变为短地图，Web、API、packages 增加就近规则。
2. 建立文档索引、核心流程规格、Harness、安全、可靠性、质量评分、技术债务和执行计划入口。
3. 用官方 `skill-creator` 流程创建 `.agents/skills/flightwoodx-development`，并通过 `quick_validate.py`。
4. 新增 `check-harness.mjs` 和 101 项测试，机械检查 16 个必需入口、元数据、链接、Skill、权限残留和受支持的静态依赖边界，并接入本地 `check` 与 GitHub CI。
5. 清理 27 个 Lark 实体 Skill、两组共 54 个遗留链接、Feishu 锁文件、旧 `fwx-motion` Skill、3 份本地权限文件和 4 份冲突的 Web 文档；旧 Vite 与资源说明改为当前入口。
6. 更新受审计影响或已弃用的依赖：`js-yaml 4.3.1`、`nanoid 3.3.18`、`@aws-sdk/client-s3 3.1111.0`、`@ungap/structured-clone 1.3.1`。
7. 独立审查发现并登记 API 路由分层、起落架规则冲突和服务端备用 DXF 源缺失；API 的备用 CAD 目录已改为 API 自有配置，现有缺件行为保持明确。
8. 为备用导出增加 `partId` 格式、零件总数、批准目录和真实路径检查；目录穿越、越界符号链接与缺失文件测试通过。
9. 备用导出改为按 owner 查询服务端 `DroneDesign` 和服务端作者；客户端作者、零件、统计与检查结果被忽略，跨用户查询返回 404。
