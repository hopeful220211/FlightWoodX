# 06 — 开发路线图（Roadmap）

> **本文档目的**：把 FlightWoodX 2026 Q2–Q4 的开发任务按优先级、依赖关系、里程碑整理出来，供人类和 Claude Code 共同参考排期。
> **口径**：季度对齐战略规划（见项目陈述文档 §5）。
> **更新频率**：每月月初更新一次，每季度做一次大复盘。

---

## 1. 三条并行轨道的技术对齐

| 轨道 | 商业目标 | 对应技术工作 |
|------|---------|-------------|
| ① 产品与软件 | 学校可交付的软硬件包 | 引导式搭建、平板 App、零件标准化 |
| ② 商业与估值 | 首批学校试点 + 500 万估值 | 多租户、班级管理、学校端数据看板 |
| ③ 学术与理论 | 《装饰》论文 + 硕士论文 | 用户行为埋点、课堂录像工具、问卷系统 |

本路线图主要覆盖轨道①与②的技术工作，轨道③的学术需求作为埋点和工具来对接。

## 7. 人力与时间假设

本路线图基于以下假设：

- 小城作为产品经理 + 前端主力，每周投入 40 小时
- Claude Code 作为「永不休息的副驾驶」，能承担约 50–60% 的代码工作
- 志豪、治远每周投入 20 小时在硬件迭代与新产品设计
- 祥子每周投入 30 小时在运营、供应链、学校 BD
- 秋宏每周投入 15 小时在内容与赛事
- 指导老师按需介入决策

如果任何人力条件变化，路线图需要同步调整。

## 8. 核心不做清单（防止范围蔓延）

以下事项 2026 年内**明确不做**：

- ❌ 用户端 App 小程序版（微信生态）
- ❌ 海外版本（新马、北美）
- ❌ 加盟商系统
- ❌ 直播课堂
- ❌ AI 辅助设计（比如「帮我推荐一个配重合理的机臂组合」）
- ❌ 区块链/NFT作品确权
- ❌ 任何非无人机的载具产品线

2027 年再评估这些是否进入路线图。

## 9. 给 Claude Code 的使用说明

1. 本文档是**活文档**，每次 Sprint 结束后更新进度。
2. 当人类提出新功能时，先对照本文档的**核心不做清单**和**优先级矩阵**评估是否当季完成，不要无条件答应。
3. 任务排期冲突时，按「M1 → M17」的里程碑编号顺序不可越级。
4. Sprint 内临时加任务，必须踢掉一个同等工时的任务（保持容量平衡），不能无限叠加。
