## 1. 背景：为什么是现在写这份 RFC

当前平台正处在 RFC-010 的 **M5 边界**：M1–M4（鉴权 / 设计器 / 积木编程器 / 模拟器）已是各自独立可用的模块，项目详情页（如 `项目 #6a3040`）已经摆出"设计 → 编程 → 试飞"三入口与"分享 / 导出"动作，但**项目级数据要到 M5 才真正灌进来、三者才闭环**——这正是你在界面上看到大量 `阶段三（M5）接入` 占位符的原因。

在把 M5 闭环拧上、并继续往 M6（参赛）M7（社区）走之前，需要先回答一个架构问题：**我们的模块边界和接入方式，是否经得起"平台从课程公司（1.0）变成赛事生态公司（2.0）"这个目标的拉扯？** 本 RFC 用国内外同类平台的实证结构来校准这件事，并把几个"现有玩家都还没做透、但与我们 2.0 战略强相关"的创新点写进目标架构。

## 2. 同类平台功能结构调研（架构层）

> 调研口径：只看**功能结构与接入方式**，不看视觉。来源为各平台官方文档 / 官网 / 行业报道（2025–2026）。

### 2.1 国际平台

**Microsoft MakeCode（micro:bit / Arcade）**
- 编辑器 = 四件套：**积木编辑器 + 文本编辑器（双向无损转换）+ 目标仿真器 + 目标代码生成器**。这套"积木↔文本↔硬件"靠 TypeScript 注解桥接，本质就是一层**指令中间表示**——和我们 RFC-010 的 `CommandProgram` IR 是同构思路，等于第三方已经验证了这条路。
- **分享即嵌入**：一个作品可分享为链接，或嵌入到博客 / 学校站，且可选择只嵌"代码 / 只读编辑器 / 仅仿真器"三种粒度；还能一键分享到 Google Classroom、Teams 等 LMS，移动端扫码打开。
- **默认可复制改编**：所有被分享的作品默认都能被别人复制后编辑（即 fork），改动不影响原作——community 的内容繁殖机制内建在分享里。
- 扩展（extensions）库 + 自带的 tutorials / skillmaps 引导式教程。

**VEXcode VR（VEX 机器人虚拟平台）**
- 核心抽象是 **Playground（可切换的虚拟任务场景）**：选择一个 Playground，**积木 / Python 工具箱会随之更新**为该场景专属指令集，场景自带场地尺寸、机器人、GPS 坐标与计分目标。——这是"场景 + 任务 + 计分"打包成可插拔单元的范式。
- **仿真成绩直推排行榜**：注册战队在赛季内于 Virtual Skills Playground 跑分，分数提交到 **Virtual Skills 排行榜**。即"模拟器产出 → 自动评分 → 竞赛排行"全线打通，纯线上即可竞赛。
- **赛季制**：每季的比赛规则在上一季世锦赛上发布，内容随赛季滚动更新。
- 语言阶梯：**积木 → Switch（积木/文本混排过渡）→ Python**；高阶场景内置 **AI 视觉传感器**。
- 商业结构：按**教师**年授权（Enhanced/Premium），一个教师授权覆盖其全部学生、校内校外通用。

**DroneBlocks（Tello 系无人机教育，与我们域最近）**
- 形态 = **积木编程 + 仿真器 + 课程 + 社区（用户互相分享 mission 代码）**。
- **仿真先行**写进产品哲学：明确类比移动开发"先在模拟器测、再上真机"，先在 3D 虚拟环境里飞、同步到账号、再一键下发真机。
- **多主题任务场景**：Minimal / City / Mars / Tundra / Egypt 等环境，每个环境配套关卡、挑战与课程（部分由 She Maps、Drone Legends 等合作方供给）。其中 **Builder 环境允许学生用方块自建关卡场景**——UGC 关卡的雏形。
- 语言阶梯：Block → Python → JavaScript → OpenCV；校级 enterprise license 无限学生、云端可在家用。

### 2.2 国内平台

**Makeblock（慧编程 mBlock / MakeX）**
- 一体化方案 = **硬件套件 + 图形化编程软件（慧编程，基于 Scratch，一键切 Python）+ 课程 + 竞赛（MakeX）+ 线上线下教程**；**500+ 机械电子零件**的金属积木搭建平台。
- 慧编程有**扩展中心**（开发者贡献的近百个扩展），支持图像识别 / 语音识别等 AI 能力与 IoT。
- 关键行业判断（多家报道）：**STEAM 教育的评价机制以"竞赛"为主（而非考试），教学载体是"软硬结合的实践平台"（而非教材）**——这恰好是我们"竞赛即留存引擎"的外部佐证。
- MakeX 赛制采用"**竞争 + 联盟共存**"：每场红蓝两联盟、各 2 支战队，需跨队结盟——一个强调协作的竞赛结构样本。

**编程猫（Codemao）**
- 三位一体：**"工具 + 内容 + 社区"**。社区是核心：**作品展厅**（孩子发布作品、获全球点赞）、**源码可见可改编**（对标 Scratch 的 remix）、**协作创造 + 相互学习**。
- **教师专区**：整套教学资源 + **班级管理工具**——B 端 / 学校层的标准配置。
- **AI 内建**：AI 辅助教学实时分析代码质量并个性化指导、AI tutor、人脸 / 手势识别、AI 绘画。
- 闭环话术：**"创作 — 分享 — 提升"**；成长路径：趣味入门 → 算法进阶 → AI 应用 → 权威赛事；另有 **3D 图形化创作工具"神奇代码岛"**（类 Roblox 的 3D UGC）。多端（PC / 平板 / 手机）打通。

### 2.3 提炼：所有人都在用的"收敛骨架"

| 共性层 | 国际 | 国内 | 我们 RFC-010 的对应 |
|---|---|---|---|
| 创作三联（设计 / 积木 / 仿真） | MakeCode（积木+文本+仿真）、DroneBlocks（积木+仿真） | 慧编程、编程猫（图形+一键 Python） | M2 设计器 + M3 编程器 + M4 模拟器 ✅ |
| **IR / 适配器解耦** | MakeCode 注解桥、VEX 场景专属指令 | 慧编程一键切 Python | `CommandProgram` IR + Adapter ✅（领先） |
| **场景 = 可插拔任务单元** | VEX Playground、DroneBlocks 环境 | （较弱） | ⚠️ RFC-010 未显式抽象，**本 RFC 补** |
| 仿真成绩 → 自动评分 → 排行 | VEX Virtual Skills 排行榜 | （较弱） | M6 参赛+排行 ✅ |
| 分享 / 嵌入 / fork | MakeCode 嵌入 + 默认可改编 | 编程猫源码改编 | ⚠️ RFC-010 仅 M7 fork，**接入契约本 RFC 补** |
| 社区 / 作品库 / 成长 | DroneBlocks mission 社区 | 编程猫展厅 + 成长路径 | M7 社区 ✅（成长体系待显式化） |
| 课堂 / 教师台 / 机构授权 | VEX 按教师授权、DroneBlocks 校级 license | 编程猫教师专区 + 班级管理 | ⚠️ RFC-010 缺，**本 RFC 补 F 层** |
| AI 内建 | VEX AI 传感器 | 编程猫 AI tutor | ⚠️ RFC-010 缺，**本 RFC 补 G 层** |
| 语言阶梯 | 积木→Switch→Python→JS | 图形→Python | 可纳入 M3 演进 |

**结论**：我们的模块清单**没有结构性缺口**，反而在 IR 解耦上领先。需要补的是四件事——**① 把"场景/任务"抽象成可插拔单元；② 把"分享/嵌入/fork/回放"做成一等公民；③ 补齐课堂/机构层（F）；④ 补齐智能层（G）**。这四件加上 §6 的创新点，构成本 RFC 相对 RFC-010 的增量。

## 3. 整体架构总览

平台按**九层 + 一条贯穿主线**组织。贯穿主线是 RFC-010 已确立的 **`CommandProgram` IR（指令中间表示）**：积木编译为 IR，所有"消费者"（模拟器 / 真机 / AR / 评分引擎）都只通过 IR 与 Adapter 接口对话——**这是全平台的硬件解耦红线，本 RFC 把它从"编程↔仿真"扩展为"编程↔一切执行/评分后端"。**

```
┌─────────────────────────────────────────────────────────────┐
│  G 智能层（横切）  AI 副驾 / AI 飞行教练 / AI 助教            │
├─────────────────────────────────────────────────────────────┤
│  I 协作层（横切）  实时协同文档（presence / 多人同编）        │
├──────────────┬──────────────┬──────────────┬─────────────────┤
│ B 创作层     │ C 项目层     │ D 竞赛层     │ E 社区层        │
│ B1 设计器    │ C1 项目聚合  │ D1 赛事/赛季 │ E1 作品库/展厅  │
│ B2 编程器    │ C2 版本/分支 │ D2 赛道场景  │ E2 零件库/零件社区│
│ B3 模拟器/试飞│ C3 分享/嵌入/回放│ D3 评分/排行 │ E3 关卡共创(UGC)│
│              │              │ D4 赛事Admin │ E4 成长体系     │
├──────────────┴──────────────┴──────────────┴─────────────────┤
│  F 教育/机构层   F1 班级+教师台 / F2 课程+教程 / F3 机构管理   │
├─────────────────────────────────────────────────────────────┤
│  A 基础层   A1 身份/角色 / A2 工作台 / A3 共享类型与 IR 协议   │
├─────────────────────────────────────────────────────────────┤
│  H 硬件接入层（P2）  H1 建造导出 / H2 真机适配器 / H3 AR 试飞  │
└─────────────────────────────────────────────────────────────┘
            贯穿主线：CommandProgram IR  ───────►  Adapter（Sim/Real/AR/Score）
```

**与 RFC-010 M 编号的映射**：A=M1，B1=M2，B2=M3，B3=M4，C1=M5，D=M6，E1/E2=M7，H=M8。**新增**：C2/C3、D2（场景抽象）、E3/E4、F 层、G 层、I 层。

## 4. 功能模块划分（各模块职责与边界）

> 每个模块标注优先级（P0 地基 / P1 生态 / P2 后续），并给出**职责边界**——边界比功能更重要，决定将来能不能独立替换。

### A 基础层

- **A1 身份与角色（P0）**：注册 / 登录（JWT）；角色 = `student / teacher / parent / admin`。边界：只管"你是谁、你能进哪些路由"，不含业务数据。
- **A2 工作台（P0）**：登录后的个人首页，聚合"我的项目 / 我报名的赛事 / 我的班级 / 我的成长"。边界：只做聚合视图与跳转，不持有领域逻辑。
- **A3 共享类型与 IR 协议（P0，全平台地基）**：`packages/shared` 统一类型；**`CommandProgram` IR 与 `DroneAdapter` 接口在此定义，禁止他处重复定义**。边界：纯类型与协议，无运行时副作用。

### B 创作层（编辑器三联，对应界面三入口）

- **B1 设计器（P0）**：参数化机身 + Three.js 3D 预览 + 三级合规（硬阻断 / 软警告 / 飞行稳定度评分）；产出 `DroneDesign`（含 glbUrl）。边界：只产出"机身结构数据"，不含飞行行为。
- **B2 积木编程器（P0，核心）**：Blockly 自定义积木集 → 编译为 `CommandProgram` IR；保存 `Program`（同存 blocklyXml 与 IR）。**演进位**：积木 ↔ 文本/Python 视图（语言阶梯，参考 MakeCode/慧编程，列为 P1）。边界：只产出 IR，**绝不直接驱动任何具体硬件或仿真实例**（红线）。
- **B3 模拟器 / 试飞（P0，核心）**：`SimAdapter implements DroneAdapter`，消费 IR 在 Three.js 场景驱动虚拟无人机；单步高亮、回放、产出可评分的 `RunResult`。**架构升级**：模拟器不再内置单一场景，而是**加载一个 Scene（见 D2）**。边界：只负责"在给定 Scene 里把 IR 跑出 RunResult"，不含计分规则（计分归 D3）。

### C 项目层

- **C1 项目聚合（P0 = 当前 M5）**：`Project = design + program`；项目详情页一键"试飞"（进模拟器）；可见性与分享。**这是你界面上 M5 占位符的归宿**。边界：把创作三联的产物绑成一个可分享、可参赛的单元。
- **C2 项目版本 / 分支（P1，创新）**：项目可存历史版本、可分支、可回滚、可 diff；fork 他人作品时记录 provenance。边界：版本是项目的元能力，不改变 design/program 的 schema。
- **C3 分享 / 嵌入 / 回放（P1，创新）**：一个 Project 或一次 Run 可生成分享链接，并支持**三种嵌入粒度**（只读项目 / 可改编编辑器 / 仅回放）——直接对标 MakeCode。边界：只读外发与改编入口，不含社区社交（社交归 E）。

### D 竞赛层

- **D1 赛事 / 赛季（P1）**：赛事列表 / 详情 / 报名；**赛季制**容器（一个 Season 绑定一套规则与赛道）。边界：组织与报到，不含计分。
- **D2 赛道 / 任务场景（P1，本 RFC 新增抽象）**：把 VEX Playground / DroneBlocks 环境的范式落地为**可插拔 Scene 包** = `{ 3D 场景资产, 该场景专属积木扩展, 计分规则 rubric, 通关/约束条件 }`。模拟器加载 Scene，工具箱按 Scene 更新。边界：Scene 是数据+规则的声明式包，不含运行时（运行时在 B3）。
- **D3 评分与排行榜（P1）**：`RunResult × rubric → Score`；排行榜；**回放可观战**。边界：纯计算 + 排序展示。
- **D4 赛事管理 Admin（P1）**：建赛、配赛道、人工复核 / 复评台。边界：运营后台，与学生端隔离。

### E 社区层

- **E1 作品库 / 展厅（P1）**：浏览、点赞、**fork/remix**（复制再创作，记录关系）。边界：作品的社交与发现。
- **E2 零件库与零件社区（P1）**：官方零件目录（`FW-[类别码]-[序号]` 命名，glb + 含卡扣点的 metadata json）+ **UGC 零件**（社区贡献、审核入库）。边界：零件是设计器的"原料目录"，与具体项目解耦。
- **E3 关卡 / 任务共创（P2，创新）**：让社区与老师用 D2 的 Scene 契约**自建赛道/关卡**（对标 DroneBlocks Builder + 编程猫神奇代码岛）。边界：UGC Scene 走与官方 Scene 相同的契约 + 审核。
- **E4 成长体系（P1，创新 = 把 2.0 的"身份阶梯"显式化）**：学徒 → 设计师 → 首席设计师 的进阶 + 徽章 + 解锁。边界：成长是横切的"积分/身份"服务，消费各模块事件（完成关卡 / 作品被 fork / 参赛名次）。

### F 教育 / 机构层（B 端学校优先战略的承载，RFC-010 缺口）

- **F1 班级 + 教师工作台（P1，B 端 P0）**：班级 / 学生名册；**作业 = 一个项目模板 + 指定 Scene/rubric**，下发给班级；提交汇总到教师看板。边界：教学组织，不改创作内核。
- **F2 课程与教程（P1）**：引导式 tutorials / skillmaps（对标 MakeCode/DroneBlocks），与课程体系绑定。
- **F3 机构 / 学校管理（P1）**：组织管理、按教师/校授权（对标 VEX/DroneBlocks 授权模型）。边界：账号与授权治理。

### G 智能层（横切，RFC-010 缺口，与"AI 时代创造者"叙事强绑定）

- **G1 AI 副驾（P1）**：编辑器内 NL→积木、设计建议。边界：建议器，最终落子仍是用户。
- **G2 AI 飞行教练（P1，差异化）**：分析 `RunResult` 给出**可执行的改进建议**（把"试错"升级为"指导"）。这是覆盖 设计→编程→试飞 全链的教练，超出编程猫只在编程环节的 AI tutor。
- **G3 AI 助教 / Tutor（P2）**：社区 / 课堂答疑。
- 全层边界：AI 服务藏在统一接口后，**模型/供应商可换**，业务模块只依赖接口不依赖具体模型。

### H 硬件接入层（P2，RFC-010 M8）

- **H1 建造导出**：激光切割图 + BOM 导出。**H2 真机适配器**：`RealDroneAdapter implements DroneAdapter`，消费**同一份 IR**，同步 mission 到设备（对标 DroneBlocks 同步上真机）。**H3 AR 试飞**。

### I 协作层（横切，创新，详见 §6）

- **I1 实时协同**：设计 / 编程文档支持多人同编 + presence（对标 Figma）。

## 5. 整体版式 / 信息架构（IA）

> 只讲**结构与层级**，不讲样式。沿用 RFC-010 的三种布局外壳，并把信息架构按 §4 的层重新组织。

### 5.1 三种布局外壳（沿用 RFC-010）

- **`AppLayout`**：顶栏 + 主导航 + 内容区——承载所有展示/管理类页面。
- **`AuthLayout`**：登录 / 注册。
- **`EditorLayout`**：全屏 + **步骤切换条（设计 → 编程 → 试飞）**——承载创作三联。**当前 `项目 #6a3040` 的三卡片即此外壳的入口投影。**

### 5.2 信息架构地图（架构级路由分组）

```
公共/鉴权        /login /register
工作台          /workbench  ← A2，聚合入口（我的项目/赛事/班级/成长）
项目（中心枢纽） /projects
                /projects/:id            ← C1 项目详情 = 引力枢纽（见 5.3）
                /projects/:id/design     ← B1（EditorLayout）
                /projects/:id/program    ← B2（EditorLayout）
                /projects/:id/fly        ← B3（EditorLayout）
                /projects/:id/history    ← C2 版本/分支
                /s/:shareId              ← C3 分享/嵌入/回放（免登录可达）
竞赛            /competitions  /competitions/:id        ← D1
                /competitions/:id/arena/:sceneId         ← D2 赛道场景
                /competitions/:id/leaderboard            ← D3（含回放观战）
社区            /community           ← E1 作品展厅
                /parts               ← E2 零件库/零件社区
                /community/arenas    ← E3 UGC 关卡共创
                /me/growth           ← E4 成长体系
课堂（B端）      /classroom           ← F1 教师工作台
                /classroom/:id/assignments               ← 作业下发/汇总
                /learn               ← F2 课程与教程
管理            /admin/...           ← D4 赛事管理 + F3 机构管理
个人            /me  /me/settings
```

### 5.3 核心 IA 原则：项目详情页是"引力枢纽"

`/projects/:id` 是整个 IA 的重心（与 F1 在 Schools / VEX 的"项目即一切"一致），它必须在一处同时挂载：**三入口（设计/编程/试飞）+ 一键试飞 + 分享/导出 + 版本/分支入口 + "提交参赛"入口 + 协作者 presence**。你截图里那个枢纽页是对的，本 RFC 只是把它的挂载点补全。**所有"散落功能"都应能从项目枢纽两跳内到达**——这是判断 IA 是否健康的硬指标。

## 6. 各功能接入方案（接入契约）

> 这是本 RFC 最核心的部分：**模块之间只通过下列契约对话**，任何绕过契约的直连都视为架构违规。契约用 TypeScript 接口示意（最终定义入 `packages/shared`）。

### 6.1 IR 指令协议（全平台脊柱，红线）

```ts
// 编程器唯一产物；模拟器/真机/AR/评分引擎唯一输入
interface CommandProgram { version: string; commands: Command[]; meta: {...} }
interface DroneAdapter {
  load(program: CommandProgram, scene: Scene): void;
  run(): Promise<RunResult>;
  step(): Promise<StepFrame>;   // 单步高亮
}
// SimAdapter / RealDroneAdapter / ARAdapter 均 implements DroneAdapter
```
**红线**：B2 只产 IR；任何"积木直接绑某款硬件 / 某个仿真实例"的写法不允许。换大疆 TT / CoDrone / 自研模块 = 只加一个 Adapter。（MakeCode 注解桥、VEX 场景指令均验证此路可行。）

### 6.2 场景 / 任务契约（D2，新增）

```ts
interface Scene {
  id: string;
  assets: SceneAssets;          // 3D 场地/障碍/目标物
  blockExtensions?: BlockDef[]; // 该场景专属积木（工具箱随场景更新）
  rubric: ScoringRubric;        // 计分规则（声明式）
  constraints: SceneConstraint[]; // 通关/约束条件
  source: 'official' | 'ugc';   // UGC 走相同契约 + 审核
}
```
模拟器（B3）加载 Scene；编程器工具箱按 `scene.blockExtensions` 扩展。**官方赛道与社区共创关卡（E3）走同一契约**——这让"内容繁殖"成为平台能力而非一次性开发。（VEX Playground + DroneBlocks Builder 范式。）

### 6.3 评分 / 排行 / 回放契约（D3）

```ts
RunResult  →  ScoringEngine(scene.rubric)  →  Score  →  Leaderboard
RunResult（可序列化遥测）= 回放数据源；回放即"可观战的 Run"
```
**模拟器不含计分，计分只读 RunResult + rubric**——评分逻辑可独立演进、可复核（D4）。仿真成绩直接进排行榜，纯线上即可办最小可行赛事（VEX Virtual Skills 验证）。

### 6.4 分享 / 嵌入 / fork 契约（C3 / E1）

```ts
share(project|run) → shareId（免登录可达 /s/:shareId）
embed 粒度: 'readonly-project' | 'editable-editor' | 'replay-only'  // 对标 MakeCode
fork(project) → newProject + provenance{ from: projectId }          // 对标 Scratch/编程猫 remix
```
**fork 默认开放 + provenance 必记**——既是社区繁殖机制，也是"从冠军作品改起"的学习路径与 E4 成长事件源。

### 6.5 AI 副驾契约（G，横切）

```ts
interface AICopilot {
  suggest(ctx: { design?, blocks?, ir?, runResult? }): Suggestion[];
}
```
编辑器把当前上下文（设计/积木/IR/RunResult）喂给统一接口，AI 返回建议；**模型/供应商藏在接口后可替换**。G2 飞行教练即 `suggest({ runResult })` 的特化。（编程猫 AI tutor、VEX AI 传感器为先例。）

### 6.6 课堂契约（F1）

```ts
Assignment = { template: ProjectTemplate, scene: SceneId, rubric, dueAt }
distribute(assignment, cohort) → 每个学生一份 Project；submissions → 教师看板
```
**作业 = 项目模板 + 指定 Scene/rubric**——复用竞赛的同一套 Scene/评分契约，B 端与竞赛端共享内核。（编程猫教师专区、DroneBlocks 校级 license。）

### 6.7 零件契约（E2）

零件库 = 版本化目录；每个零件 = `glb + metadata.json(含卡扣点) + FW 命名`。设计器（B1）只消费目录，不内嵌零件。UGC 零件走"贡献 → 审核 → 入库"，与官方零件同 schema。（Makeblock 500+ 零件平台范式 + 你现有飞书 BOM 命名规范。）

### 6.8 硬件适配契约（H，P2）

`RealDroneAdapter` / `ARAdapter` 均 implements `DroneAdapter`，消费**同一份 IR**——这正是 §6.1 红线的兑现。（DroneBlocks 同步上真机为先例。）

### 6.9 协作契约（I，创新）

设计/编程文档以 **CRDT/OT** 承载多人同编 + presence；项目文档从"单人单写"升级为"多人共享文档"。（Figma 范式，详见 §6 创新点 1。）

## 7. 颠覆性 / 创新性改进（按"杠杆/成本比"排序）

> 每条标注与 2.0 战略的绑定关系、优先级、风险。**高杠杆低成本的排在前面，建议先做。**

**① 作品即社交货币：可回放、可观战、可嵌入（P1，最高战略契合）**
每次 Run 产出可分享回放，可一键嵌入小红书 / 学校站 / 朋友圈。这把你"将孩子的喜悦转化为家长的社交货币"的核心命题**变成平台原生能力**，且直接喂养你 90% 投入的小红书渠道——每个学生作品都是一个营销面。成本低（建在 §6.3/6.4 契约上），杠杆极高。**建议第一个做。**

**② AI 飞行教练（P1，差异化护城河）**
分析 `RunResult` 给可执行改进建议，覆盖 设计→编程→试飞 全链。这是"创造者，而非消费者"叙事在 AI 时代的最强落点，且超出编程猫只在编程环节的 AI tutor。建在 §6.5 契约上，可增量上线。

**③ 场景/任务 SDK + UGC 共创（P2，内容引擎）**
把赛道/关卡做成可插拔 Scene（§6.2）并开放给社区与老师共创（E3）。**让社区成为内容繁殖器**，大幅降低你的内容生产成本，并直接为竞赛与人才管道供血（对应 5 支柱里的"设计平台与零件社区""赛事生态"）。风险：需配审核与质量门槛。

**④ 成长身份阶梯系统化（P1，留存引擎）**
把"学徒 → 设计师 → 首席设计师"从口号做成一等平台系统（徽章/层级/解锁，E4），消费各模块事件。这是你 2.0"身份阶梯驱动多年参与"论断的工程兑现。成本中等，留存收益高。

**⑤ 项目版本 / 分支（P1，教育价值 + 战略）**
版本/分支/回滚/diff（C2）。一方面教"迭代纪律"（恰好对症你自我识别的成长边——缩小想象与执行的差距）；另一方面支撑"从冠军设计 fork 再创作"。建在项目元层，schema 不动。（Onshape/Git 范式。）

**⑥ 实时协同创作（P2，差异化但偏重）**
设计/编程多人同编（I1，§6.9）。**几乎没有教育竞品做透**，且天然支撑"战队协作参赛"（呼应 MakeX 的联盟协作赛制）。风险：CRDT/OT 工程量大、与现有单写数据模型有冲突，**建议排在 ①②④ 之后、作为竞赛战队功能的配套再上**。

**⑦ 零件创作者经济（P2，桥接套件经济）**
UGC 零件 → 审核 → 精选 → 最终可转化为可购买套件（E2），把平台与"套件经济"支柱打通。属长线，待社区与零件库到规模后启动。

## 8. 约定与红线（沿用 RFC-010 + 本 RFC 新增）

**沿用 RFC-010：**
- 跨前后端类型全部来自 `packages/shared`，禁止重复定义。
- **硬件解耦红线**：积木 ↔ 执行/评分后端只经 IR + Adapter。
- 禁 `eval`；积木程序走 JS-Interpreter 沙箱。
- 不在前端硬编码密钥；三态（加载/空/错误）是每个数据页硬性要求。
- 每模块独立分支 / 独立 PR / 截图证据协议；本类文档为 `docs/` 唯一事实来源。

**本 RFC 新增架构红线：**
- **场景红线**：模拟器不得内嵌单一场景；一切场景经 Scene 契约加载（§6.2）。
- **评分红线**：计分逻辑不得写进模拟器；只读 `RunResult + rubric`（§6.3）。
- **AI 红线**：业务模块不得直依赖某个具体模型/供应商，只依赖 `AICopilot` 接口（§6.5）。
- **课堂复用红线**：作业不得另起一套评测；必须复用竞赛的 Scene/rubric 契约（§6.6）。
