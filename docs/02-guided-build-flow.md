# 02 — 引导式搭建流程（Guided Build Flow）

> **本文档目的**：定义 FlightWoodX 设计工作台从「自由拖拽」重构为「分步引导式搭建」的完整产品规格。
> **重构原因**：目前 6–12 岁小朋友第一次打开设计工作台会手足无措——左边一个零件库、中间一张空白网格、右边一个检查面板，他们不知道「应该先放什么、再放什么」。真实课堂中老师要花 10 分钟反复喊「先选主板！」，这违背了 STEAM 教育「让学生自主探索但不失控」的原则。
> **设计目标**：引导式 ≠ 机械式。要让小朋友**在规定的搭建顺序中依然保有设计自由度**（比如必须在第 1 步选主板，但主板有 9 种可选；必须在第 2 步装支架，但支架有 35 种可选、数量可在 3/4/6 之间自选）。

---

## 1. 核心理念：Scaffolding（脚手架理论）

引用维果茨基（Vygotsky）的「最近发展区」与 Wood, Bruner, Ross 的「Scaffolding」理论：

> 学习者在能独立完成的任务和需要协助才能完成的任务之间，存在一个「最近发展区」。教师（或在我们这里是软件）的角色是**搭脚手架**——在需要时给予支持，在掌握后及时撤走。

翻译到本产品：

- **新手模式（默认）**：强制分步，每一步完成后解锁下一步，当前步骤之外的零件**不可交互**（灰度 + 禁用）。
- **熟练模式**：完成过至少 1 架完整无人机后，解锁「自由设计模式」，恢复早期的全开放拖拽。
- **老师端**：老师可在课堂上切换整班模式。

本文档主要定义新手模式。

---

## 2. 搭建步骤全景图

基于零件的**结构依赖关系**与**飞行可行性**，搭建被拆为 6 步：

```
Step 1  主板 (HUB)           ← 一切的基础，决定整机布局
  │
Step 2  机臂 (ARM)           ← 装在主板上，数量决定是四轴/六轴/八轴
  │
Step 3  电机 + 螺旋桨 (电子)  ← 安装在机臂末端（电子元件，非木件）
  │
Step 4  保护罩（三选一）      ← PLATE 一体 / JOINT 分体 / LAND 半体
  │
Step 5  衔接件 (DECO)        ← 固定双层结构（如果有）
  │
Step 6  命名 + 预览 + 飞行检查 ← 软合规提醒 + 飞行稳定度评分
```

> 注：课程里原有的「机翼 / 尾翼」分类在新无人机（四/六轴旋翼无人机）中**不存在**。旧线上那两个 tab 要在迁移后移除，或保留为将来"木质船舶""木质飞翼机"产品线的预留，暂不展示。

## 3. 每一步的详细规格

### Step 1 — 选择主板（HUB）

#### 产品文案
- **标题**：第 1 步 · 选一块主板
- **一句话说明**：主板是无人机的「心脏」，所有零件都连接在它上面。
- **帮助气泡**（点问号弹出）：不同形状的主板适合不同的飞行风格：圆形稳、十字形灵活、多边形个性。

#### 可选项
- 9 块主板（`core_hub_01.glb` ~ `core_hub_09.glb`），以**预渲染 PNG 卡片**展示（解决 WebGL Context 溢出的根本方案）。
- 点击卡片 → 在中央画布出现 3D 预览（单个 WebGL Canvas，整个工作台共享）。
- 选中后右下角出现「确认使用」按钮。

#### 完成条件
- 用户点击「确认使用」后，该主板进入画布中央，锁定旋转/平移，`project.stepReached` 从 0 升到 1。

#### 可撤销性
- 进入 Step 2 之前可以自由换主板。
- 进入 Step 2 之后点「回上一步」会弹确认：「换主板会清空已加的机臂，继续吗？」

#### 数据写入
```ts
project.parts.push({
  id: 'hub',
  partNumber: 'FW-HUB-001',
  position: [0, 0, 0],
  rotation: [0, 0, 0],
  locked: false,
});
project.stepReached = 1;
```

---

### Step 2 — 安装机臂（ARM）

#### 产品文案
- **标题**：第 2 步 · 装上机臂
- **一句话说明**：机臂伸展出去，末端会挂电机。多装几只机臂，无人机飞得更稳，但也更重。
- **帮助气泡**：4 臂最常见（叫「四轴」），6 臂更稳（叫「六轴」），8 臂用于载重。

#### 交互规则
- 在 Step 1 选定的主板上，预置的「卡扣点」（snap point，来自 GLB 的元数据 JSON）会**高亮闪烁**，每个卡扣点显示一个半透明的「+ 加机臂」图标。
- 左侧零件库只显示 ARM 类别（35 个），其他类别 tab 灰显。
- 点击一个卡扣点 → 弹出「选择机臂款式」面板（小型浮窗，4 列网格）。
- 选定款式 → 机臂**对称地**同时安装到所有镜像卡扣点（比如选了一条，就在中心对称的另一条位置也安装一条，保证配平）。
- 机臂数量最少 3（三轴，特殊飞行风格），最多 8（八轴）。

#### 为什么要对称安装？
6–12 岁小朋友做非对称无人机 100% 飞不起来，会严重打击信心。对称策略既保留选择自由（选哪款机臂），又保障物理可行。

#### 完成条件
- 至少安装了 3 条机臂（或偶数对：2/4/6/8）对。
- 用户点击「下一步」。

#### 边界情况
- 用户可以撤销（「-」按钮）最后安装的对称对。
- 如果主板上所有卡扣点都有机臂后仍点「加机臂」，提示「这款主板最多只能装 N 条机臂，换一款试试？」

---

### Step 3 — 安装电机与螺旋桨（电子元件）

#### 产品文案
- **标题**：第 3 步 · 装电机和螺旋桨
- **一句话说明**：电机让螺旋桨转起来，螺旋桨把空气向下推，无人机就飞起来了。
- **帮助气泡**（点击看原理动画）：这就是升力原理（Step 3 的内容 → 跳转到学习中心对应课时）。

#### 交互规则
- 每条机臂末端预置一个卡扣点，展示半透明电机图标。
- 电机分 3 档（根据机臂长度和重量预估自动推荐）：
  - 小型（7mm，适合机身总重 <50g）
  - 中型（8.5mm，50–100g）
  - 大型（10mm，>100g）
- 螺旋桨颜色可选：黑 / 白 / 红（纯外观）。
- 数量必须和机臂数相等（自动强制）。

#### 重要设计决策
电机和螺旋桨是**电子元件**，不是木件。在线上学习模式里是**可视化表达**，不参与 GLB 3D 构建，仅在数据模型里记录。**实体课堂**里，老师发放对应型号的电机和螺旋桨，学生按在线设计的规格组装。

#### 完成条件
- 每条机臂都装了电机和螺旋桨。

---

### Step 4 — 选保护罩（三选一）

#### 产品文案
- **标题**：第 4 步 · 给螺旋桨穿上「保护圈」
- **一句话说明**：飞行中最怕螺旋桨碰到墙或人。保护罩是无人机的「安全带」。
- **帮助气泡**：三种保护罩各有优缺点——

#### 三种模式对比（UI 上用并排卡片展示）

| 类型 | 文件 | 外观 | 优点 | 缺点 | 适合 |
|------|------|------|------|------|------|
| **一体版** | `core_plate_XX.glb` | 一整块环绕式保护罩 | 保护最强、最稳 | 最重、最费木料 | 初学者、室内飞行 |
| **分体版** | `joint_XX.glb` | 四个分开的小保护罩 | 更轻、更灵活 | 保护面积小 | 中级、有控制基础 |
| **半体版** | `Landing_XX.glb` | 一半一半的保护罩 | 折中，兼顾重量与保护 | 视觉最复杂 | 进阶个性化 |

（以上"适合"标签仅作课堂引导，不阻断学生选择。）

#### 交互规则
- 三张大卡片横排展示，每张有预渲染照片 + 3 个对比维度（保护性 / 重量 / 灵活度）的条形图。
- 点击一张卡片 → 展开该类型下的 6–11 个具体款式 → 再选一款。
- 选定后在画布上**动画式安装**（上方飞入，旋转对齐到卡扣点）。

#### 完成条件
- 选定并确认一款保护罩。

---

### Step 5 — 衔接件（DECO，可选）

#### 产品文案
- **标题**：第 5 步 · 加装饰衔接件（可跳过）
- **一句话说明**：如果你选了双层主板，衔接件把上下两层连起来，让结构更牢固。
- 如果 Step 1 选的主板是**单层**，**本步骤自动跳过**并提示：「你的主板是单层的，不需要衔接件，直接到下一步吧 →」。
- 如果是**双层**，衔接件必选。

#### 交互规则
- 与 Step 2 类似，在主板上的 DECO 卡扣点高亮闪烁。
- 衔接件不落地（不作支撑），只固定上下主板，要求**对称安装**。

---

### Step 6 — 命名 + 预览 + 飞行检查

#### 产品文案
- **标题**：第 6 步 · 给你的无人机起个名字，看看它能不能飞！
- **一句话说明**：我们会帮你分析整机结构，给出一个「飞行稳定度」分数。

#### 交互规则
- 输入框：作品名称（默认「我的第 N 架无人机」）。
- 点击「运行飞行检查」→ 右侧展示 4 个指标：
  1. **总重量**：自动累加所有木件 + 电机 + 螺旋桨质量。
  2. **重心位置**：计算几何中心与重量分布中心的偏差（mm）。
  3. **推重比**：电机最大推力 / 总重量。健康值 > 2.0。
  4. **对称性得分**：结构对称度百分比。
- 三级柔性合规：
  - 🟢 **可飞行**：所有指标达标 → 解锁「发布到作品展示」按钮。
  - 🟡 **可以试飞但有风险**：某一项指标警戒 → 警告 + 建议优化 + **仍允许发布**（标注「实验版」）。
  - 🔴 **无法飞行**：物理不可能的结构（如两条机臂重叠）→ 阻断发布，但允许发布为「艺术概念版」（不飞，只展示）。

#### 完成条件
- 用户确认保存或发布。

## 4. 状态机（State Machine）

用 XState 或类似库实现。伪代码：

```ts
type BuildStep = 'HUB' | 'ARM' | 'MOTOR' | 'GUARD' | 'DECO' | 'REVIEW';

const buildMachine = createMachine({
  id: 'drone-build',
  initial: 'HUB',
  context: {
    project: { parts: [], stepReached: 0 },
  },
  states: {
    HUB: {
      on: {
        SELECT_HUB: { actions: 'addHub' },
        CONFIRM: {
          cond: 'hasHub',
          target: 'ARM',
          actions: 'advance',
        },
      },
    },
    ARM: {
      on: {
        ADD_ARM_PAIR: { actions: 'addArmPair', cond: 'canAddMoreArms' },
        REMOVE_ARM_PAIR: { actions: 'removeLastArmPair' },
        CONFIRM: { cond: 'hasMinArms', target: 'MOTOR', actions: 'advance' },
        BACK: { target: 'HUB', actions: 'warnDataLoss' },
      },
    },
    MOTOR: { /* ... */ },
    GUARD: {
      on: {
        SELECT_GUARD_TYPE: { actions: 'setGuardType' },
        SELECT_GUARD_MODEL: { actions: 'setGuardModel' },
        CONFIRM: { target: 'DECO', actions: 'advance' },
      },
    },
    DECO: {
      always: {
        cond: 'hubIsSingleLayer',
        target: 'REVIEW',
        actions: 'skipDeco',
      },
      on: { /* ... */ },
    },
    REVIEW: {
      on: {
        SAVE: { actions: 'saveProject' },
        PUBLISH: { cond: 'passesSafetyCheck', actions: 'publishProject' },
      },
    },
  },
});
```

## 6. 数据模型变更

### `projects` collection schema 增加：
```ts
interface Project {
  // ... 原有字段
  buildMode: 'guided' | 'free'; // 默认 guided
  stepReached: 0 | 1 | 2 | 3 | 4 | 5 | 6; // 已完成到哪一步
  parts: PartInstance[]; // 已有
  safetyCheck?: {
    weight: number; // 克
    centerOfMass: [number, number, number];
    thrustToWeight: number;
    symmetryScore: number; // 0–1
    level: 'green' | 'yellow' | 'red';
  };
}

interface PartInstance {
  partNumber: string; // FW-HUB-001
  category: 'HUB' | 'ARM' | 'MOTOR' | 'PROP' | 'PLATE' | 'JOINT' | 'LAND' | 'DECO';
  position: [number, number, number];
  rotation: [number, number, number];
  snapToPartId?: string; // 吸附的父零件 id
  snapToPointId?: string; // 吸附的父零件 snap point id
}
```

### `users` collection 增加：
```ts
interface User {
  // ... 原有
  completedBuilds: number; // 完整搭建完成的无人机数量，用于解锁「自由模式」
}
```

## 7. 迁移策略

1. **保留现有自由拖拽代码**：放在 `/design/free` 路由下，仅对 `completedBuilds >= 1` 的用户开放。
2. **新用户默认进入 `/design/guided`**。
3. 现有用户首次登录迁移后，根据 `completedBuilds` 自动路由。
4. 管理后台增加「强制所有用户使用引导模式」的开关（课堂场景）。

---

## 8. 测试用例（给 Claude Code 写自动化测试用）

每一步至少覆盖：
- ✅ Happy path（标准完成）
- ✅ 回退（撤销到上一步）
- ✅ 边界数量（最少机臂 / 最多机臂）
- ✅ 跨步数据一致性（主板换了，已加的机臂要清空）
- ✅ 单层主板自动跳过 DECO 步骤
- ✅ 合规检查的三个颜色等级都能正确触发

## 9. 给 Claude Code 的执行清单

1. 先在 `docs/rfcs/RFC-001-guided-build-flow.md` 写出完整 RFC（含你对本文档的疑问与改进建议），提交人类确认。
2. 确认后，按以下顺序编码：
   1. 数据模型迁移（数据库 schema + Mongo migration script）
   2. 状态机（XState 或自研）
   3. 每一步的 UI 组件（可以先不做动效）
   4. 路由与模式切换
   5. 合规检查规则引擎（Step 6）
   6. 动效与细节打磨
   7. 测试用例
3. 每完成一个子步骤，发 PR 并等 review，不要全部做完再一次性提交。
